# Shift V1 — contractor marketplace

Shift V1 turns the workspace into a job board for contract work in construction and
manufacturing: a verified **credential wallet**, an eligibility-gated **For You** feed,
offers, and a **schedule lock** mirrored to Google Calendar. The CP-SAT crew planner
(SHIFT Adaptive, see `ADAPTIVE.md`) stays as a business-side tool at `/planner`.

## Try it

1. Start the API and web app as in the README, then open http://127.0.0.1:3000.
2. Click **Continue with Google**. Without Google keys the server sends you to
   `/signin/demo`, which lists fictional accounts (`@demo.shift.local`).
3. Demo worker **Maya Brooks**: 6 eligible contracts, 1 offer waiting, WHMIS expiring
   next week, no Fall Protection ticket. Demo business **Northline Homes** (Alex Morgan):
   3 applicants on “Finish carpenter, show homes”.
4. Rehearse again from a clean state at **/dev/reset** (refused outside demo mode).

## Google setup (when you have keys)

Create a Google Cloud **OAuth client (Web application)** with redirect URI
`http://127.0.0.1:3000/api/v1/auth/google/callback`, add every demo account as a test
user, then set `SHIFT_GOOGLE_CLIENT_ID`, `SHIFT_GOOGLE_CLIENT_SECRET`,
`SHIFT_TOKEN_ENCRYPTION_KEY` and (outside demo mode) `SHIFT_SESSION_SECRET` — see
`.env.example`. Sign-in asks only for `openid email profile`; Calendar access is asked
for separately when the worker adds a contract to their calendar.

**Honest limitation:** the Google sign-in and Calendar code paths are covered by tests
with Google's HTTP calls stubbed, but have **not** been run against real Google yet.
The `.ics` download works without any Google setup.

## How it works

- **Data** (`market_models.py`): users, worker_profiles, organizations (+ business/agency
  fields), org_members, credential_types (catalog as data), credentials, work_history,
  postings, posting_requirements, contract_applications, engagements,
  availability_blocks, connected_accounts, notifications, audit_log. On PostgreSQL every
  new table has RLS enabled with client roles revoked: browsers reach data only through
  the FastAPI boundary, which enforces ownership per request.
- **Eligibility** (`feed.py`): a required ticket is green when verified, amber when held
  but unverified (blocking only if “must be verified”), red when missing, expired or
  rejected. Booked dates come from active engagement blocks.
- **Schedule lock** (`schedule.py`, `engagements.py`): exclusive contracts block the whole
  range; part-time contracts block only worked days. Acceptance re-checks tickets and
  overlaps, then writes blocks in one transaction (row lock on PostgreSQL).
- **Privacy**: proof documents live in `SHIFT_UPLOAD_DIR`, are type-checked by magic
  bytes, and are served only through 5-minute signed links to the owner, Shift admins
  and businesses the worker applied to. Site addresses appear only with an offer.
  Manual “Unavailable” reasons are visible only to the worker.
